LLM inference · lossless acceleration

Guess fast, check once.

An LLM writes one token per forward pass, and each pass spends most of its time waiting for memory. Speculative decoding lets a small model draft several tokens and the big model verify them all in one pass. The trick is a rejection-sampling rule, which keeps the output distribution exactly the same as the big model alone. This page covers the hardware reason, the algorithm, the full proof, and the speedup maths.

01

Why decoding is slow: prefill is compute-bound, decode is memory-bound

What matters is arithmetic intensity: how many FLOPs you do per byte you load from HBM. GPUs compute far faster than they can load data, so a kernel with low intensity spends its time waiting.

Take one weight matrix $W\in\mathbb{R}^{H\times H}$ in 16-bit (2 bytes per number). The GPU must load it from HBM before it can use it. What changes between the two phases is how many tokens share that one load.

Prefill: the whole prompt at once (GEMM)

$$\underbrace{2PH^2}_{\text{FLOPs}}\ \Big/\ \underbrace{2H^2}_{\text{bytes}}\ \approx\ P\ \ \text{FLOP/byte}\qquad(P=\text{prompt tokens})$$

Decode: one new token (GEMV)

$$2\cdot1\cdot H^2\ \Big/\ 2H^2\ \approx\ 1\ \ \text{FLOP/byte}\qquad(\times B\ \text{with batch size}\ B)$$

H100's balance point (dense BF16)

$$\frac{989\ \text{TFLOP/s}}{3.35\ \text{TB/s}}\approx 295\ \text{FLOP/byte}$$

Prefill with $P=2048$ is well above 295, so the Tensor Cores are the bottleneck: it is compute-bound. Decode at batch 1 sits at about 1 FLOP/byte, roughly 300× below the balance point. The maths finishes almost instantly, then the cores wait for the next layer's weights to arrive. Decode is memory-bound.

The loophole speculative decoding exploits: checking $k+1$ tokens in one pass loads the weights once and moves intensity from 1 to about $k+1$. It is still far below 295, so it costs about the same wall-clock time as generating 1 token.

Even the final logits step works the same way: $h\in\mathbb{R}^{1\times H}$ times $W_U\in\mathbb{R}^{H\times V}$ with $V$ = 32 K–128 K is another GEMV. The maths takes microseconds; loading $W_U$ is what costs time.

02

The KV-cache tax, and why it can't live in SRAM

Every decode step also reads the whole KV cache, the stored keys and values of every past token in every layer. That data grows linearly with context, while the work done on it stays tiny.

$$\text{KV bytes / token}=2\cdot L\cdot H_{kv}\cdot d_h\cdot b=2\cdot80\cdot8\cdot128\cdot2=327{,}680\ \text{B}\approx320\ \text{KiB}\quad(\text{Llama-2-70B})$$

SRAM sits on the die next to the cores and is extremely fast. But each bit takes 6 transistors, so there is very little of it. HBM is DRAM stacked on the package: 80–192 GB, but much slower to reach. So the cache has to live in HBM, and every new token pays to stream it through.

Batching helps, up to a point. Serving $B$ requests together (continuous batching, as in vLLM) turns a GEMV into a GEMM and multiplies intensity by $B$. But each request brings its own KV cache, so HBM capacity caps $B$. Memory sets the limit again.
03

The idea: draft cheaply, verify in parallel

The work is split into two phases that repeat until <eos>.

✏️

Draft

A small model $q$ (say 1 B parameters) generates $k$ candidate tokens one by one. Each step is cheap, and it records $q(\tilde x_i)$ for each token.

🔍

Verify

The large model $p$ (say 70 B) runs one forward pass over prefix + $k$ drafts and gets $k+1$ next-token distributions at once.

⚖️

Accept / correct

Rejection sampling keeps the longest acceptable prefix, then adds one corrected or bonus token from $p$. There is always at least one new token.

04

Formal definition

Let the target model define $p(x_i\mid x_{\lt i})$, and the draft model $q(x_i\mid x_{\lt i})$.

Standard autoregressive decoding needs $N$ sequential target passes to produce $N$ tokens, each a memory-bound GEMV. The goal is to produce $\hat x_1,\dots,\hat x_N$ such that

$$P\left(\hat x_i\mid\hat x_{\lt i}\right)=p\left(\hat x_i\mid\hat x_{\lt i}\right)\quad\text{for every } i,$$

so the output is identically distributed to the target model's own samples, while using as few target forward passes as possible. That is what "lossless" means here: not "close to", but exactly the same distribution.

Notation alert. This page uses Leviathan et al. (2023): $p$ = target, $q$ = draft, accept with $\min(1,p/q)$. DeepMind's paper (Chen et al., 2023) swaps the letters: there $q$ is the target and $p$ the draft, so the rule reads $\min(1,q/p)$. It is the same algorithm. Always check which letter is the big model.
05

The algorithm, step by step

One round, given the prefix $x_{\lt t}$ and draft length $k$:

Step 1 · Autoregressive drafting

$$\tilde x_{t},\dots,\tilde x_{t+k-1}\sim q(\cdot\mid\cdot)\quad\text{(store each }q(\tilde x_i\mid x_{\lt i})\text{)}$$

Step 2 · Parallel verification (one target pass)

$$p(\tilde x_i\mid x_{\lt i})\ \ \text{for}\ i=t..t{+}k{-}1,\qquad \text{plus}\ \ p(\cdot\mid x_{\lt t+k})$$

Step 3 · Modified rejection sampling, left to right

$$r_i\sim U(0,1),\qquad \text{accept }\tilde x_i\ \text{ if }\ r_i\lt\min\!\left(1,\ \frac{p(\tilde x_i)}{q(\tilde x_i)}\right)$$ $$\text{first rejection at } i:\ \ x_i\sim p'(x)=\frac{\max\left(0,\ p(x)-q(x)\right)}{\sum_{x'}\max\left(0,\ p(x')-q(x')\right)},\ \ \text{discard the rest}$$

Step 4 · Bonus token

$$\text{all }k\text{ accepted}\ \Rightarrow\ x_{t+k}\sim p(\cdot\mid x_{\lt t+k})\quad(\text{already computed in step 2})$$

If $p\ge q$ for the drafted token, it is always accepted: the draft was not overconfident. If $p\lt q$, it is accepted with probability $p/q$. Each round therefore yields between 1 and $k+1$ tokens.

Simulator: one speculative round

Context: "The future of AI is" · k = 4 · toy distributions (each position has fixed p and q). Draft, then verify with real random draws.
Output so far: "The future of AI is"
def speculative_round(prefix, draft, target, k=4):
    xs, qs = [], []
    for _ in range(k):                               # ① cheap, sequential
        q = draft(prefix + xs); x = sample(q); xs.append(x); qs.append(q)
    ps = target(prefix, xs)                              # ② ONE pass → k+1 distributions
    out = []
    for i, x in enumerate(xs):                          # ③ left to right
        if random() < min(1, ps[i][x] / qs[i][x]):
            out.append(x)                                #    accepted
        else:
            resid = (ps[i] - qs[i]).clamp(min=0)
            out.append(sample(resid / resid.sum()))       #    corrected token
            return out
    out.append(sample(ps[k]))                            # ④ bonus token
    return out
06

Proof: the output is exactly $p$

Fix a prefix and drop it from the notation. There are exactly two disjoint ways the algorithm can output token $x$.

Event A · the draft proposes x and it is accepted

$$P(A)=q(x)\cdot\min\!\left(1,\frac{p(x)}{q(x)}\right)=\min\left(p(x),\,q(x)\right)$$

Total rejection probability

$$P(\text{reject})=\sum_w q(w)\left(1-\min\!\left(1,\tfrac{p(w)}{q(w)}\right)\right)$$ $$=\sum_w\left(q(w)-\min(p(w),q(w))\right)=\sum_w\max\left(0,\,q(w)-p(w)\right)$$

Both distributions sum to 1, so the two "excess masses" are equal

$$\sum_w\max(0,\,q(w)-p(w))=\sum_w\max(0,\,p(w)-q(w))\ \equiv\ Z$$

Event B · a rejection, then x is drawn from the residual

$$P(B)=P(\text{reject})\cdot p'(x)=Z\cdot\frac{\max(0,\,p(x)-q(x))}{Z}=\max\left(0,\,p(x)-q(x)\right)$$

Add them

$$P(\text{output}=x)=\min(p(x),q(x))+\max(0,\,p(x)-q(x))=p(x)\qquad\blacksquare$$

Check both cases: if $p(x)\ge q(x)$ the sum is $q(x)+(p(x)-q(x))=p(x)$. If $p(x)\lt q(x)$ it is $p(x)+0=p(x)$. Rejection removes the draft's overconfident mass, and the residual adds back exactly what the draft under-predicted.

A probability subtlety from my notes. Event A is a joint event, "draft = x and accepted", not the marginal "draft = x". In general $$P(X=Y,\,Y=a)=P(X=a,\,Y=a)\le P(X=a),$$ with equality only if $X=a$ forces $Y=a$. That's why the proof needs Event B too: the joint term alone is never the whole story.

Monte-Carlo check: does the scheme really reproduce p?

Draft q is deliberately wrong. Run the accept/resample rule many times and compare the empirical histogram with the target p.
07

How much faster?

Let $\alpha$ be the acceptance rate (the probability a drafted token survives). Each round yields the accepted prefix plus one token, so

$$\mathbb{E}[\text{tokens per target pass}]=1+\alpha+\alpha^2+\dots+\alpha^{k}=\frac{1-\alpha^{k+1}}{1-\alpha}$$

Drafting costs $k$ small-model steps. If one draft step costs $c$ times a target step, the round takes $(1+kc)$ target-step equivalents, and the expected wall-clock speedup is

$$\text{speedup}\approx\frac{1-\alpha^{k+1}}{(1-\alpha)(1+kc)},\qquad \alpha=\sum_x\min(p(x),q(x))=1-\tfrac{1}{2}\|p-q\|_1$$

So α is literally the overlap between the two distributions: one minus half their total-variation distance. A draft that thinks like the target gives a high α.

08

Where do the drafts come from?

A separate draft model is the classic version, but it adds deployment friction. Several methods avoid a second model.

MethodHow it draftsExtra training?
Separate draft modelA smaller LLM from the same family and tokenizer (e.g. ~1 B for a ~70 B target)None (or distil it for a higher α)
MedusaSeveral extra decoding heads on the target's last hidden state, each predicting token t+1, t+2, …Train the heads
EAGLEA ~1-layer module predicts the target's next hidden states autoregressively; the frozen LM head turns them into tokensTrain the small module
Prompt lookupCopy n-grams that already appear in the prompt or output (great for RAG, code edits, summaries)None

EAGLE in more detail

EAGLE works at the feature level. The target's top-layer hidden state for the latest token goes, together with the token's embedding, into a lightweight draft module (about one Transformer layer). The module predicts the next hidden state, the target's frozen LM head maps it to a token, and the process repeats. Because it conditions on the target's own rich features, its drafts match the target closely: high α.

$$\hat f_{t+1}=g_\phi\left(f_t,\ e(x_{t+1})\right),\qquad \tilde x_{t+2}\sim\mathrm{softmax}\left(W_U\,\hat f_{t+1}\right)\qquad(W_U\ \text{frozen, shared with the target})$$

Yes, the module must be trained, but cheaply. Three points matter:

  • Train on the target's own outputs, not human text. Run prompts (e.g. ShareGPT, UltraChat) through the frozen target, and record its responses and hidden states.
  • Freeze the target. Only the small module $g_\phi$ gets gradients, with a feature-regression loss plus a token-level loss (cross-entropy / KL against the target's distribution).
  • Fight drift. At inference the module feeds on its own previous predictions. EAGLE-3's training-time test unrolls several draft steps during training, so the module learns to recover from its own errors.
09

Deploying it: keep the models together

Every round trades sub-millisecond messages between drafter and verifier, so communication latency kills the gain. Never put them on different servers.

🧩

Same GPU

Small pairs (e.g. 7 B target + 1 B draft) share one GPU's HBM, so hand-off is essentially free.

🔗

Same node

A 70 B target is tensor-parallel over 4–8 GPUs. The draft is replicated or squeezed alongside, and NVLink (≈ 900 GB/s on H100) carries the traffic.

🎯

One model

Medusa / EAGLE heads live inside the target process: no second weights, no second KV cache, no transfer. This is why serving stacks like vLLM favour them.

When it helps less: at large batch sizes decode is already closer to compute-bound, so the "free" verification capacity shrinks. Speculative decoding shines at small batches: interactive chat, coding assistants, voice agents where time-to-audio matters.
10

Recap

  • Why it works: decode is a memory-bound GEMV (≈ 1 FLOP/byte vs the H100's ≈ 295), so verifying k + 1 tokens in one pass costs about one step.
  • Algorithm: draft k tokens with q → one target pass → accept each with $\min(1,p/q)$ → on the first reject sample from $\max(0,p-q)$ → bonus token if all are accepted.
  • Lossless: $\min(p,q)+\max(0,p-q)=p$, so the output distribution is exactly the target's.
  • Speed: $\mathbb{E}[\text{tokens/pass}]=\frac{1-\alpha^{k+1}}{1-\alpha}$ with $\alpha=1-\tfrac12\|p-q\|_1$; speedup ≈ that ÷ (1 + kc).
  • Drafts: a separate small model, Medusa heads, EAGLE (trained feature extrapolator), prompt lookup, lookahead. Co-locate everything.
