A memory that chooses.

A vanilla RNN overwrites its memory at every step, so old information fades. A Long Short-Term Memory (LSTM) network keeps a separate cell state and uses three gates to decide what to erase, what to write and what to reveal. This page builds the cell gate by gate, with a live calculator you can drive.

01

The problem LSTM solves

In a vanilla RNN, $h_t = \tanh(W_{xh}x_t + W_{hh}h_{t-1})$. Every step pushes the whole memory through the same matrix and a squashing function.

That causes two problems, both covered in the RNN blog. In the forward pass, old information is overwritten: a pulse seen at step 1 shrinks by roughly $|W_{hh}|$ every step. In the backward pass, the gradient is a product of one Jacobian per step, so it vanishes or explodes exponentially. In practice a vanilla RNN struggles to use anything more than about 10–20 steps back.

Hochreiter and Schmidhuber's 1997 answer was to give the network a second state, the cell state $c_t$, that is updated by addition rather than by repeated matrix multiplication. Learned gates control that addition.

📝

RNN = whiteboard

Every step you wipe the board and rewrite a blurred copy plus the new note. After a while the old notes are unreadable.

📒

LSTM = notebook

You keep a notebook. Each step you cross out some lines (forget), add some lines (input) and read out a summary (output). Untouched lines stay sharp.

02

The cell-state highway

The most important line in an LSTM is this one:

$$c_t = f_t \odot c_{t-1} \;+\; i_t \odot g_t$$

The old memory $c_{t-1}$ is multiplied element by element ($\odot$) by the forget gate $f_t \in (0,1)$, and new content $i_t \odot g_t$ is added. There is no weight matrix and no tanh between $c_{t-1}$ and $c_t$. Now look at the gradient along this path:

$$\frac{\partial c_t}{\partial c_{t-1}} = \mathrm{diag}(f_t) \qquad\Longrightarrow\qquad \frac{\partial c_T}{\partial c_1} = \prod_{t=2}^{T} \mathrm{diag}(f_t)$$

If the network learns $f_t \approx 1$ for a unit, that unit's memory and its gradient pass through many steps almost unchanged. The network learns how long to remember, unit by unit, instead of being forced to forget at a fixed rate. This is sometimes called the constant error carousel.

Connection you already know: this is the same idea as a residual connection in a ResNet or Transformer, $x_{l+1} = x_l + F(x_l)$. An additive path lets gradients flow. The LSTM had it in 1997, along time instead of along depth.
03

Four gates, one input

Every gate reads the same thing: the previous hidden state and the current input, concatenated as $[h_{t-1}, x_t]$. Each has its own weights $W_\ast \in \mathbb{R}^{H\times(H+d)}$ and bias.

🧽

Forget gate $f_t$

$\sigma(W_f[h_{t-1},x_t]+b_f)$. Between 0 and 1 per unit: 0 = erase this memory, 1 = keep it.

🚪

Input gate $i_t$

$\sigma(W_i[h_{t-1},x_t]+b_i)$. How much of the new candidate to write into each unit.

✍️

Candidate $g_t$

$\tanh(W_g[h_{t-1},x_t]+b_g)$. The new content itself, in $(-1,1)$. Also written $\tilde c_t$.

🔦

Output gate $o_t$

$\sigma(W_o[h_{t-1},x_t]+b_o)$. Which parts of the memory to expose as $h_t$.

$$h_t = o_t \odot \tanh(c_t)$$

Why sigmoid for gates and tanh for content? A gate is a soft switch, so $(0,1)$ is the natural range. Content should be able to push memory both up and down, so it uses $(-1,1)$. The final $\tanh(c_t)$ keeps $h_t$ bounded even if $c_t$ has grown large.

04

One LSTM step, by hand

A 1-unit LSTM with $x_t = 1$, $h_{t-1} = 0.5$, $c_{t-1} = 0.8$ and small made-up weights. Step through the computation in the order the cell does it.

Gates first, then memory, then output

x=1 · h_(t−1)=0.5 · c_(t−1)=0.8
gates f = 0.690σ(0.5x+0.4h+0.1) i = 0.611σ(0.6x−0.3h) g = 0.762tanh(0.9x+0.2h) o = 0.679σ(0.7x+0.1h)
cell state 0.552f·c₋ = 0.690·0.8 0.465i·g = 0.611·0.762 c = 1.017keep + write
output 0.769tanh(c) h = 0.522o·tanh(c)

Notice the cell state went up from 0.8 to 1.017. The network kept 69% of the old memory and added new content on top. A vanilla RNN can't do this: its new state is always a squashed mix, never "old plus new".

Set b_f = −4: $f \approx 0.02$ and the old memory is wiped, so $c_t$ is almost exactly $i \cdot g$. Set b_f = +4: $f \approx 0.99$ and $c_{t-1}$ passes through. This is why practitioners initialise the forget bias to +1 (Jozefowicz et al., 2015): the cell starts out remembering and learns when to forget.
06

Memory over time: RNN vs LSTM

Feed a single pulse at step 1, then zeros. The vanilla RNN's memory is multiplied by $w_h$ and squashed every step. The LSTM's cell state is multiplied only by its forget gate.

How long does a pulse survive?

coral = RNN h_t · teal = LSTM c_t · dashed = 10% of the start value

Half-life is $\ln 0.5 / \ln f$ steps. With $f = 0.99$ a memory lasts about 69 steps before halving; with $f = 0.999$, about 693. The RNN can't simply raise $w_h$ to 1 because the same matrix also mixes in every new input and goes through tanh, which saturates.

07

GRU and other variants

The Gated Recurrent Unit (GRU, Cho et al. 2014) merges the cell and hidden state and uses two gates instead of three.

$$z_t = \sigma(W_z[h_{t-1},x_t]) \quad r_t = \sigma(W_r[h_{t-1},x_t]) \quad \tilde h_t = \tanh(W_h[r_t\odot h_{t-1},x_t])$$ $$h_t = (1-z_t)\odot h_{t-1} + z_t \odot \tilde h_t$$

The update gate $z_t$ plays the role of forget and input together: what it keeps, it doesn't write. The reset gate $r_t$ decides how much of the old state the candidate may look at. Full deep-dive: GRU blog →

08

PyTorch: an LSTM cell from scratch

All four gates come from one matrix multiply, then get split. This is exactly how the fused kernels do it.

import torch, torch.nn as nn

class TinyLSTMCell(nn.Module):
    def __init__(self, d, H):
        super().__init__()
        self.lin = nn.Linear(d + H, 4 * H)       # W_i, W_f, W_g, W_o stacked
        with torch.no_grad():
            self.lin.bias[H:2*H].fill_(1.0)     # forget-gate bias = +1

    def forward(self, x, state):              # x: (B, d)
        h, c = state                              # each (B, H)
        i, f, g, o = self.lin(torch.cat([h, x], -1)).chunk(4, -1)
        i, f, o = torch.sigmoid(i), torch.sigmoid(f), torch.sigmoid(o)
        g = torch.tanh(g)
        c = f * c + i * g                         # the highway
        h = o * torch.tanh(c)
        return h, c

B, T, d, H = 4, 50, 128, 256
cell, x = TinyLSTMCell(d, H), torch.randn(B, T, d)
h = c = torch.zeros(B, H)
for t in range(T):
    h, c = cell(x[:, t], (h, c))

# built-in: cuDNN-fused, multi-layer
lstm = nn.LSTM(d, H, num_layers=2, batch_first=True, dropout=0.1)
out, (h_n, c_n) = lstm(x)
print(out.shape, h_n.shape, c_n.shape)     # (4,50,256) (2,4,256) (2,4,256)
print(sum(p.numel() for p in nn.LSTM(d, H).parameters()))   # 395,264
Why 395,264 and not 394,240? PyTorch keeps two bias vectors per layer, bias_ih and bias_hh, each of size $4H$. So the count is $4H(d+H) + 8H = 4\cdot256\cdot384 + 2048$. PyTorch's gate order inside those stacked weights is i, f, g, o, which matters when you set the forget bias or port weights to ONNX/TensorRT.

09

LSTMs in speech recognition

Before Conformers, LSTMs were the standard speech encoder. Today they are mostly found in the decoder side of transducer models.

ModelWhere the recurrence is
Graves et al. 2013, DeepSpeech 2 (2015)The encoder: stacked bidirectional LSTMs (Graves) or GRUs/RNNs (DeepSpeech 2) over audio frames, trained with CTC.
Listen, Attend and Spell (2015)A pyramidal BiLSTM encoder that halves the frame rate per layer, plus an LSTM decoder with attention.
RNN-Transducer (Graves 2012) and TDTThe prediction network: an LSTM (often 1–2 layers, H ≈ 640) reads the previous non-blank tokens and acts like a small language model.
Conformer, FastConformer, ParakeetEncoder replaced by attention + convolution. The RNN-T/TDT predictor is still an LSTM.
When you deploy an RNN-T or TDT model, the LSTM predictor runs once per emitted token inside the greedy-decoding loop, carrying $(h, c)$ between calls. That is why the predictor and joiner are usually exported as separate ONNX graphs with the states as explicit inputs and outputs. See the decoder-families A4 sheet and the FastConformer sheet.
10

Interview questions

QuestionStrong short answer
How does LSTM solve vanishing gradients?The cell state is updated additively, $c_t = f\odot c_{t-1} + i\odot g$, so $\partial c_t/\partial c_{t-1} = \mathrm{diag}(f_t)$, with no weight matrix or tanh′. With $f\approx1$ the gradient passes through many steps.
Name the gates and their activations.Forget, input and output gates use sigmoid (0–1 switches). The candidate $g$ uses tanh (signed content). Output: $h = o\odot\tanh(c)$.
Difference between $h_t$ and $c_t$?$c_t$ is long-term memory, internal and additive. $h_t$ is the gated, squashed view of it that is exposed as output and fed to the gates.
Parameter count of one LSTM layer?$4H(d+H+1)$, or $4H(d+H)+8H$ in PyTorch (two biases). With d=128, H=256: 395,264.
Why initialise the forget bias to 1?So $f\approx0.73$ at start: the cell remembers by default and gradients flow early in training.
LSTM vs GRU?GRU: 2 gates, no separate cell, ¾ of the params, often similar accuracy. LSTM: separate memory, slightly stronger on long dependencies.
Can LSTMs still explode?Yes. The gradient through $h_t$ and the gates still involves weight matrices, so gradient clipping is still standard.
Why did Transformers replace LSTMs?LSTMs need T sequential steps (no parallel training over time) and squeeze all history through a fixed $h_t$. Attention connects any two positions directly and trains in parallel.
Forget a little, write a little, reveal a little.
