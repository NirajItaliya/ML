01

Why accuracy alone fools you

Imagine a disease that affects 1 in 100 people. A lazy model that always predicts "healthy" is right 99% of the time — 99% accuracy — and catches exactly zero sick patients.

That's the trap. A single number hides what kind of mistakes a model makes. On imbalanced data — fraud, disease, defects, spam — the rare class is the whole point, and accuracy quietly rewards ignoring it. To see the real story we need to split "wrong" into its two flavours: crying wolf (false alarms) and missing the wolf (misses). That split is the confusion matrix, and precision, recall and F1 all flow from it.

🎯

Accuracy

Overall correctness. Honest on balanced data, misleading when one class is rare.

🔍

Precision

When the model says "positive," how often is it right? Punishes false alarms.

🕸️

Recall

Of all the real positives, how many did it catch? Punishes misses.

02

The confusion matrix — where every metric is born

A confusion matrix is a 2×2 table comparing what actually happened (rows) with what the model predicted (columns). Four cells, four outcomes.

✅

True Positive (TP)

Predicted positive, and it really was. A correct hit — e.g. flagged fraud that was fraud.

✅

True Negative (TN)

Predicted negative, and it really was. A correct pass — e.g. a normal email left in the inbox.

⚠️

False Positive (FP)

Predicted positive, but it wasn't. A false alarm — Type I error. Good email sent to spam.

❌

False Negative (FN)

Predicted negative, but it was positive. A miss — Type II error. A disease left undetected.

The cost is rarely symmetric. A false negative on a cancer screen can be fatal; a false positive on a spam filter loses a real email. Which error you fear most decides which metric you optimize — that's the whole game.

04

Accuracy — overall correctness

The fraction of all predictions that were right, of either kind.

$$ \text{Accuracy}=\frac{TP+TN}{TP+TN+FP+FN} $$

What it answers: "Out of everything I predicted, how much did I get right?" When to trust it: balanced datasets where the classes are roughly equal and both error types cost the same. When it lies: imbalanced data — the rare-disease model that scores 99% by never predicting the disease.

Rule of thumb: if one class is much rarer than the other, treat accuracy as a sanity check, not a verdict. Look at precision and recall for the real picture.
05

Precision — how trustworthy is a "yes"?

Of everything the model labelled positive, what fraction truly was positive? Precision is punished by false positives.

$$ \text{Precision}=\frac{TP}{TP+FP} $$

How to read it

Precision lives entirely in the "predicted positive" column. It asks: when the model raises its hand, how often should you believe it? No false positives → 100% precision. The more junk that sneaks into the positive pile, the worse it looks.

How to calculate it — worked example

Say a spam filter flags 100 emails as spam. 90 really were spam (TP = 90), 10 were innocent (FP = 10):

$$ \text{Precision}=\frac{90}{90+10}=\frac{90}{100}=0.90\;\;(90\%) $$

When precision matters most

When a false positive is expensive. A spam filter that sends real mail to junk, a system that blocks legitimate transactions, a court tool that wrongly flags someone — all want high precision: only say "positive" when you're sure.

def precision(tp, fp):
    return tp / (tp + fp) if (tp + fp) else 0.0

precision(90, 10)   # of all "spam" calls, how many were right?
0.9 # 90% of flagged emails really were spam
06

Recall — how many real positives did we catch?

Of all the actual positives in the data, what fraction did the model find? Recall is punished by false negatives. Also called sensitivity or true positive rate.

$$ \text{Recall}=\frac{TP}{TP+FN} $$

How to read it

Recall lives entirely in the "actual positive" row. It asks: of everything that truly was positive, how much did we manage to catch? Miss nothing → 100% recall. Every false negative drags it down.

Worked example

A cancer screen is run on 100 patients who truly have the disease. It correctly flags 70 (TP = 70) and misses 30 (FN = 30):

$$ \text{Recall}=\frac{70}{70+30}=\frac{70}{100}=0.70\;\;(70\%) $$

When recall matters most

When a false negative is dangerous. Disease screening, fraud detection, predictive maintenance, search — better to raise a few false alarms than to miss a real case. Here you tolerate lower precision to push recall up.

def recall(tp, fn):
    return tp / (tp + fn) if (tp + fn) else 0.0

recall(70, 30)     # of all real cases, how many did we catch?
0.7 # caught 70% of the patients who were actually sick
07

F1 score — one number for the balance

Precision and recall pull in opposite directions. F1 is their harmonic mean — a single score that's only high when both are high.

$$ F_1 = 2\cdot\frac{\text{Precision}\cdot\text{Recall}}{\text{Precision}+\text{Recall}} $$

Why harmonic (not plain average) mean? Because it refuses to be fooled by a lopsided model. If precision = 1.0 but recall = 0.0, the plain average is a comfy 0.5 — but F1 is 0. You can't game F1 by acing one metric and ignoring the other; it punishes imbalance.

Worked example

With precision = 0.90 and recall = 0.70:

$$ F_1 = 2\cdot\frac{0.90\times0.70}{0.90+0.70}=2\cdot\frac{0.63}{1.60}=0.7875 $$
The general form: $F_\beta$ lets you weight recall more ($\beta>1$) or precision more ($\beta<1$). $F_2$ favours recall (medicine); $F_{0.5}$ favours precision (recommendations). $F_1$ weights them equally.
08

The threshold trade-off & PR curve

A classifier outputs a probability; a threshold turns it into a yes/no. Slide that threshold and you slide along the precision–recall trade-off.

Lower the threshold and the model says "positive" more freely: it catches more real positives (recall ↑) but also raises more false alarms (precision ↓). Raise it and the opposite happens. You almost never get both high at once — squeezing one usually costs the other.

The PR curve traces every threshold's (recall, precision) pair. It's more informative than the ROC curve on imbalanced data. Want one summary number? The area under it (average precision) rewards models that keep precision high across all recall levels.

10

Metrics vs loss — and how to track both

A subtle but vital distinction: the loss is what the model trains to minimize; the metrics are how humans judge it. They are not the same thing.

Loss (e.g. cross-entropy) must be smooth and differentiable so gradient descent can optimize it; it reacts to the model's probabilities. Accuracy, precision, recall and F1 are computed on the final labels and are often non-differentiable — great for reporting, useless as a training signal. So you train on loss and watch the metrics.

$$ \text{Binary cross-entropy} = -\frac{1}{N}\sum_{i}\big[y_i\log p_i + (1-y_i)\log(1-p_i)\big] $$

How to check the loss (and metrics) during training

Track loss and a task-appropriate metric on a held-out validation set every epoch. If training loss keeps falling while validation loss climbs, you're overfitting — stop early. Watch the metric you actually care about (often F1 or recall), not just accuracy.

from sklearn.metrics import precision_score, recall_score, f1_score, log_loss

for epoch in range(epochs):
    train_loss = train_one_epoch(model, train_loader)      # what we minimize
    val_probs  = model.predict_proba(X_val)[:, 1]
    val_pred   = (val_probs >= 0.5).astype(int)            # threshold → labels

    val_loss = log_loss(y_val, val_probs)                  # probability quality
    p  = precision_score(y_val, val_pred)
    r  = recall_score(y_val, val_pred)
    f1 = f1_score(y_val, val_pred)
    print(f"ep{epoch}  train_loss={train_loss:.3f}  val_loss={val_loss:.3f}  "
          f"P={p:.3f}  R={r:.3f}  F1={f1:.3f}")

    if val_loss > best + patience_eps:    # early stopping on validation loss
        break

Watch the gap. Falling train loss + rising validation loss = overfitting. The metric you report (F1/recall) should be measured on validation/test data the model never trained on — never on the training set.
11

Which metric, when — the decision guide

Pick the metric that matches the cost of being wrong in your problem.

Choosing a metric by scenario
SituationOptimize forWhy
Balanced classes, equal error costAccuracySimple and honest when no class dominates.
False positives are costly (spam filter, blocking transactions)PrecisionOnly say "positive" when confident; avoid false alarms.
False negatives are dangerous (disease, fraud, safety)RecallCatch every real case, even at the cost of some false alarms.
Both errors matter; imbalanced dataF1 scoreOne number that stays low unless precision and recall are both high.
Comparing models across all thresholdsPR-AUC / ROC-AUCThreshold-free; PR-AUC is best when positives are rare.
Probabilities must be well-calibratedLog lossPunishes confident mistakes; measures probability quality.
One sentence to remember: precision is "don't cry wolf," recall is "don't miss the wolf," F1 is "do both," and accuracy is "how often right overall" — trustworthy only when the classes are balanced.
