Why normalize at all?

A deep network is a tower of matrix multiplies. Each layer's output becomes the next layer's input — so small distribution shifts compound.

As gradients flow backward through many layers they tend to either vanish (shrink toward zero, so early layers stop learning) or explode (blow up, so updates become wild). On the forward pass, the distribution of activations drifts layer to layer — sometimes called internal covariate shift. The practical effect is the same: training gets slow and unstable.

Normalization fixes this by re-standardizing activations at chosen points so each layer keeps receiving inputs with a sane, predictable scale. The differences between our three methods come down to one question: across which direction do you compute the statistics?

01

The one idea behind all three

Every method here is the same three-step recipe. Only the axis of the statistics changes.

$$ \hat{x} = \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} \qquad\qquad y = \gamma\,\hat{x} + \beta $$

Subtract a mean μ, divide by a spread √(σ²+ε), then let the network re-scale (γ) and re-shift (β) if it wants to. The tiny ε just stops division by zero. RMSNorm later drops the mean step and β entirely — but the skeleton is identical.

Picture your activations as a matrix: rows = examples in the batch, columns = features. The only difference between the methods is the arrow direction:

BatchNorm  statistics computed down each column — one feature, all examples.

LayerNorm  statistics computed across each row — one example, all its features.

RMSNorm  also across each row, but only the magnitude (root-mean-square), no centering.

03

BatchNorm across the batch

Batch Normalization was the first widely adopted technique and a genuine turning point: networks suddenly trained faster, tolerated higher learning rates, and cared less about clever weight initialization.

Intuition — grading on a curve, per subject. Imagine a class (the batch) where each subject is a feature: Math, Physics, Art. BatchNorm curves each subject independently using everyone's scores in that subject. Your Math score becomes "how many standard deviations above the class Math average." It only works if the class is big enough — curve a subject with 2 students and the "average" is noise.
$$ \mu_j=\frac{1}{N}\sum_{i=1}^{N}x_{ij}\quad \sigma_j^2=\frac{1}{N}\sum_{i=1}^{N}(x_{ij}-\mu_j)^2\quad y_{ij}=\gamma_j\frac{x_{ij}-\mu_j}{\sqrt{\sigma_j^2+\epsilon}}+\beta_j $$

The catch: train ≠ inference

At inference you might feed a single example — there is no batch to average over. So BatchNorm keeps a running mean and running variance during training and uses those frozen stats at test time. That bookkeeping is real overhead, and it's the root of most BatchNorm bugs.

# BatchNorm: stats DOWN the batch dimension (dim 0)
class BatchNorm1d:
    def __call__(self, x):           # x: [N examples, D features]
        if self.training:
            mean = x.mean(0, keepdim=True)  # one mean per feature
            var  = x.var(0,  keepdim=True)  # one var  per feature
            self.run_mean = .9*self.run_mean + .1*mean   # remember for inference
            self.run_var  = .9*self.run_var  + .1*var
        else:
            mean, var = self.run_mean, self.run_var      # frozen stats
        xhat = (x - mean) / (var + self.eps).sqrt()
        return self.gamma * xhat + self.beta

Strengths & limits at a glance

Good: smooths the loss surface, enables higher learning rates, mild regularization (each sample is normalized using its batch-mates).

Bad: needs a decently large batch for reliable stats; awkward in distributed training (stats must sync); breaks with batch size 1; the train/inference mismatch must be managed carefully.

04

LayerNorm across the features

LayerNorm flips the axis. Instead of standardizing a feature using the batch, it standardizes one example using its own features. The batch is no longer involved at all — which removes BatchNorm's biggest headaches in one move.

Intuition — each student normalizes their own report card. Forget the class. You take your own scores across all subjects, subtract your average, divide by your spread. No classmates needed — works with a class of one. That's why a Transformer can normalize a single token's vector on its own, mid-sequence, with nobody else around.
$$ \mu_i=\frac{1}{D}\sum_{j=1}^{D}x_{ij}\quad \sigma_i^2=\frac{1}{D}\sum_{j=1}^{D}(x_{ij}-\mu_i)^2\quad y_{ij}=\gamma_j\frac{x_{ij}-\mu_i}{\sqrt{\sigma_i^2+\epsilon}}+\beta_j $$

The formula is the twin of BatchNorm — only the sum runs over j (features) instead of i (examples). Because each row is self-sufficient, there are no running statistics and the behavior is identical in training and inference.

# LayerNorm: stats ACROSS the feature dimension (dim 1)
class LayerNorm1d:
    def __call__(self, x):           # x: [N examples, D features]
        mean = x.mean(1, keepdim=True)   # one mean per example
        var  = x.var(1,  keepdim=True)   # one var  per example
        xhat = (x - mean) / (var + self.eps).sqrt()
        return self.gamma * xhat + self.beta   # no running stats, ever

Why it owns sequence models

Batch-size independent (works at batch 1), simple in distributed setups, consistent train/test, and perfect for variable-length sequences. It is the standard inside Transformers like BERT and GPT for exactly these reasons.

05

RMSNorm rescale only

RMSNorm asks a sharp question: do we actually need the mean-subtraction? In high dimensions the re-centering step contributes surprisingly little, so RMSNorm drops it — keeping only the rescaling by the root-mean-square. It also drops β.

Intuition — don't recenter, just resize. LayerNorm both recenters (subtract your average) and resizes (divide by your spread). RMSNorm says "skip the recentering, just shrink-or-stretch my whole score sheet so its overall magnitude is standard." Fewer steps, one fewer parameter, and in practice the model barely notices the missing recenter — so you keep the speed.
$$ \text{RMS}(x_i)=\sqrt{\frac{1}{D}\sum_{j=1}^{D}x_{ij}^2+\epsilon}\qquad y_{ij}=\gamma_j\,\frac{x_{ij}}{\text{RMS}(x_i)} $$
# RMSNorm: divide by root-mean-square, no centering, no beta
class RMSNorm1d:
    def __call__(self, x):           # x: [N, D]
        ms = (x**2).mean(1, keepdim=True)  # mean of squares per example
        return self.gamma * x / (ms + self.eps).sqrt()

Why LLMs love it

Fewer operations than LayerNorm, one fewer parameter (no bias), comparable accuracy, and good numerical stability. That efficiency compounds across hundreds of layers and trillions of tokens — which is why it appears in models like LLaMA and PaLM.

06

Inside a Transformer block

A common question: when embeddings from the attention layer pass through LayerNorm, what comes out — and how does it differ from sending the feed-forward output through LayerNorm?

The honest answer first: LayerNorm does the exact same thing to both. It takes each token's vector (length d_model) and standardizes it across its own features, independent of every other token and position. The operation doesn't know or care whether the vector came from attention or the FFN. What differs is the kind of vector being fed in — and therefore what the normalization is "cleaning up."

Precisely what gets normalized: in the original encoder, LayerNorm runs on the sum x + Attention(x), not on the attention output alone. In the pre-norm style shown in the figure, it runs on the sublayer's input. Sections 10–11 explain both.

Stage A — after attention

Self-attention makes each token's output a weighted mix of other tokens' value vectors. So the vector entering LayerNorm here is "contextual" — pooled across positions. Different tokens attend to wildly different neighbours, so their raw magnitudes and means vary a lot. LayerNorm forces every token vector back to mean 0, variance 1 (then applies γ, β), so the next sublayer receives uniformly scaled inputs regardless of how much "mixing" each token underwent.

Stage B — after the feed-forward network

The FFN is position-wise: the same little MLP (expand → non-linearity → project back) applied to each token separately, no cross-token mixing. Its output magnitudes are shaped by the non-linearity (ReLU/GELU can leave large positive spikes). LayerNorm again standardizes each token vector across its features — same math — but now it's taming per-token nonlinear blow-ups rather than cross-token mixing.

So how does the output differ? The normalization rule is identical row-by-row. The statistics differ because the inputs differ: attention feeds context-pooled vectors, the FFN feeds position-wise nonlinear vectors. After LayerNorm, both are re-standardized to the same clean distribution — that uniformity is the whole point of a norm after each sublayer.

Why LayerNorm and not BatchNorm here?

Stack tokens × batch and the "batch axis" becomes ill-defined: sequences have different lengths, and a token's statistics would leak across unrelated sentences. At generation time you often process one token with batch size 1 — BatchNorm has nothing to average over. LayerNorm sidesteps all of it by normalizing within a single token vector. That independence is why Transformers are a LayerNorm/RMSNorm world, not a BatchNorm one.

07

When to use which — and why not the others

Use BatchNorm when…

You're training CNNs or feed-forward nets on fixed-size inputs with healthy batch sizes (image classification, batches of 32–256). The batch gives stable per-feature statistics and the regularization is a bonus.

why not LayerNorm/RMSNorm? They'd work, but you'd lose the batch-level regularization and the well-tuned BatchNorm recipes vision architectures are built around.

Use LayerNorm when…

You have sequences, variable lengths, tiny batches, online/streaming data, or distributed training — anything where examples must be normalized independently (RNNs, Transformers).

why not BatchNorm? Unstable or undefined batch stats (small/variable batches, batch 1 at inference), cross-example leakage, and painful synchronization. LayerNorm removes every one.

Use RMSNorm when…

You're building large-scale Transformers where every FLOP and parameter counts, and you've found (as the field has) that mean-centering isn't pulling its weight.

why not full LayerNorm? You'd pay for a mean-subtraction and a bias parameter that barely move the accuracy needle. RMSNorm gets near-identical quality for less compute — at LLM scale that saving is enormous.
Practitioner's shortcut. For NLP / Transformer work, reach for RMSNorm with pre-normalization (normalize before each sublayer, inside the residual branch). Pre-norm keeps the residual stream clean and spares you the extra normalization post-norm needs around skip connections.

09

The "Add": residual connections

Before LayerNorm ever runs, the Transformer does something even simpler. It adds the sublayer's input back to its output.

$$ \text{out} = x + F(x) $$

Here \(F\) is the sublayer (attention or the FFN). Instead of replacing \(x\) with \(F(x)\), the layer keeps \(x\) and only adds a correction on top. \(F\) no longer has to learn the whole transformation, only the change (the "residual") that improves \(x\).

Analogy: editing a document with track changes. Each layer doesn't rewrite the essay from scratch. It suggests edits on top of the current draft. If a layer has nothing useful to add, it can suggest zero edits (\(F(x)\approx 0\)) and the draft passes through untouched.

Why it saves the gradients

Take the derivative of the output with respect to the input:

$$ \frac{\partial\,(x + F(x))}{\partial x} \;=\; \underbrace{I}_{\text{identity: always 1}} \;+\; \frac{\partial F(x)}{\partial x} $$

Without the residual, the gradient reaching layer 1 of an \(L\)-layer stack is a product of \(L\) Jacobians. If each one shrinks the signal a little, the product vanishes. With the residual, every layer contributes \(I + \partial F/\partial x\), and expanding the product always leaves one term that is just \(I\cdot I\cdots I\). There is a direct gradient highway from the loss to the very first layer, whatever the depth.

Gradient highway: plain stack vs. residual stack

Each layer multiplies the backward signal by a factor f. Watch how much reaches layer 1.
Plain: gradient = fdepth
Residual: identity path alone = 1
Bars show the gradient reaching each layer, from the top layer (left) to layer 1 (right). For the residual stack we plot only the guaranteed identity path, which stays at 1 at every depth. Other paths add to it, so the total never depends on fL alone.
This is why the original Transformer could stack 6 + 6 layers, and why modern LLMs can stack 80+. Without residuals, deep Transformers barely train at all.
10

Add & Norm, exactly as the paper does it

Every sublayer in the original Transformer is wrapped in the same three operations: dropout → add → LayerNorm.

$$ \text{out} = \text{LayerNorm}\big(\,x + \text{Dropout}(\text{Sublayer}(x))\,\big) $$
Correction to section 06: in the original encoder, LayerNorm is not applied to the attention (or FFN) output on its own. It is applied to the sum \(x + \text{Sublayer}(x)\). In the modern pre-norm style, it is applied to the sublayer's input instead (section 11). In neither version does LayerNorm see the bare sublayer output.

One encoder layer = two Add & Norm blocks

$$ A = \text{LayerNorm}_1\big(X + \text{Dropout}(\text{MultiHead}(X))\big) $$ $$ \text{Out} = \text{LayerNorm}_2\big(A + \text{Dropout}(\text{FFN}(A))\big) $$

The add only works because the sublayer's output has exactly the same shape as its input (n × 512). That's why attention projects back with \(W^O\) and the FFN shrinks 2048 → 512.

Where dropout goes (Pdrop = 0.1 in the paper)

  • On each sublayer's output, before the residual add (shown above).
  • On the sum of embedding + positional encoding at the bottom of the stack.
  • Most implementations also apply it to the attention weights after the softmax, and inside the FFN after the activation.

Post-LN vs. Pre-LN: where the norm sits

The 2017 paper put LayerNorm after the residual add (Post-LN). Almost every model since GPT-2 puts it before the sublayer, inside the branch (Pre-LN).

Post-LN vs. Pre-LN
Post-LNPre-LN
FormulaLN(x + F(x))x + F(LN(x))
Residual pathPasses through a LayerNorm in every layerPure identity from the embeddings to the top
Gradient flowGradients near the output are large and get rescaled at every LN, so training is fragile when deepSmooth: the identity highway from section 09 is fully intact
Learning-rate warmupEssential (the paper used 4,000 warmup steps)Much less sensitive, often trains without long warmup
Extra pieceNoneA final LayerNorm after the last layer, because the stream itself is never normalized
QualityCan be slightly better when it trains successfullyVery stable. In very deep stacks, later layers can contribute less
Used byOriginal Transformer, BERT, RoBERTaGPT-2/3, ViT, T5, Llama / Mistral (with RMSNorm)
Why does Pre-LN train more easily? In Post-LN, each layer's output is renormalized, so the identity term from section 09 gets rescaled by the LN's Jacobian at every layer. The highway exists, but it has a toll booth in every layer. Pre-LN moves the LN into the side branch, so the main road \(x \to x + \cdots \to x + \cdots\) is unobstructed. Xiong et al. (2020), "On Layer Normalization in the Transformer Architecture", analyzes this in detail.
12

The feed-forward network (FFN)

Attention mixes information between tokens. The FFN then processes each token's mixed vector on its own, with the same small MLP for every position.

$$ \text{FFN}(a) = \max(0,\; aW_1 + b_1)\,W_2 + b_2 \qquad W_1\in\mathbb{R}^{512\times2048},\; W_2\in\mathbb{R}^{2048\times512} $$
Step by step for one token
StepOperationShape
0 · inputa = output of the first Add & Norm512
1 · expandh = a·W₁ + b₁2048
2 · activate ★r = ReLU(h) = max(0, h), element-wise. The only activation function in the layer2048
3 · dropoutTraining only (common placement)2048
4 · project backy = r·W₂ + b₂, with no activation afterwards512
5 · Add & NormLayerNorm(a + y)512

Why expand to 4× and come back?

The wide hidden layer gives each token 2048 "pattern detectors". Each neuron fires when the token's vector points in its preferred direction. Projecting back to 512 keeps the shape compatible with the residual add and with the next layer. Research on trained models suggests the FFN acts like a key–value memory: \(W_1\)'s columns detect patterns and \(W_2\)'s rows write the associated information back into the token.

Why the activation is essential

$$ (aW_1 + b_1)W_2 + b_2 \;=\; a\,\underbrace{(W_1W_2)}_{W'} + \underbrace{(b_1W_2 + b_2)}_{b'} $$

Without ReLU, the two linear layers collapse into one 512×512 linear map, so 2.1 M parameters would do the work of 262 k. ReLU breaks the collapse and lets the FFN learn non-linear functions. The FFN holds about two-thirds of each layer's parameters.

One token through the second half of the layer

This puts sections 09 to 12 together on real numbers: add → norm → FFN → add → norm (Post-LN, as in the original encoder).

Toy sizes: \(d_{model}=4\), \(d_{ff}=8\) (still 4×), \(\gamma = 1\), \(\beta = 0\), no dropout. All numbers below are computed live.

Notice three things. (1) After each LayerNorm, the vector has mean 0 and variance 1 again. (2) ReLU switched off of the 8 hidden neurons for this token. (3) Both residual adds kept the earlier signal: the final vector is still clearly related to the input, with the FFN's correction on top.
14

Code: a full encoder layer, both styles

import torch, torch.nn as nn

class FeedForward(nn.Module):
    def __init__(self, d_model=512, d_ff=2048, p=0.1):
        super().__init__()
        self.w1, self.w2 = nn.Linear(d_model, d_ff), nn.Linear(d_ff, d_model)
        self.drop = nn.Dropout(p)
    def forward(self, a):
        return self.w2(self.drop(torch.relu(self.w1(a))))     # ReLU only between W1 and W2

class EncoderLayer(nn.Module):
    def __init__(self, d_model=512, h=8, d_ff=2048, p=0.1, pre_norm=False):
        super().__init__()
        self.attn = nn.MultiheadAttention(d_model, h, dropout=p, batch_first=True)
        self.ffn  = FeedForward(d_model, d_ff, p)
        self.ln1, self.ln2 = nn.LayerNorm(d_model), nn.LayerNorm(d_model)
        self.drop = nn.Dropout(p)
        self.pre_norm = pre_norm

    def forward(self, x, pad_mask=None):
        if self.pre_norm:                                      # x + F(LN(x))
            h = self.ln1(x)
            x = x + self.drop(self.attn(h, h, h, key_padding_mask=pad_mask)[0])
            x = x + self.drop(self.ffn(self.ln2(x)))
        else:                                                  # LN(x + F(x)), the original paper
            x = self.ln1(x + self.drop(self.attn(x, x, x, key_padding_mask=pad_mask)[0]))
            x = self.ln2(x + self.drop(self.ffn(x)))
        return x

layer = EncoderLayer()
print(sum(p.numel() for p in layer.parameters()))   # 3,152,384  (attention 1,050,624 + FFN 2,099,712 + 2 LN 2,048)
