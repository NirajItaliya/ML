Two gates are enough.

The Gated Recurrent Unit (GRU) keeps the LSTM's big idea, an additive path through time, but drops the separate cell state and the output gate. It has one state, two gates and about ¾ of the parameters. This page builds the cell, works one step by hand and gives you a live gate lab.

01

Why a GRU exists

The LSTM solved the vanishing-gradient problem, but it carries two states and four weight blocks. In 2014 Cho et al. asked: how much of that is really needed?

A vanilla RNN forgets because it pushes its whole memory through a matrix and a tanh at every step. The LSTM fixes this with an additive cell state guarded by forget, input and output gates. The GRU keeps only the essential part: an additive, gated path through time. It applies that path directly to the hidden state.

🎚️

One slider, not two

LSTM's forget and input gates are tied into one update gate $z$: keep a fraction $1-z$ of the old state, take a fraction $z$ of the new candidate.

🧹

A reset button

A new reset gate $r$ lets the candidate ignore the past. That's useful at a sentence or word boundary.

🪶

Lighter

One state and 3 weight blocks instead of 4. That's 25% fewer parameters and FLOPs per step than an LSTM of the same width.

02

The cell: four lines

Both gates read the same concatenation $[h_{t-1}, x_t]$. The candidate reads a reset version of the past.

$$r_t = \sigma(W_r[h_{t-1}, x_t] + b_r) \qquad z_t = \sigma(W_z[h_{t-1}, x_t] + b_z)$$ $$\tilde h_t = \tanh\!\big(W_h[\,r_t \odot h_{t-1},\; x_t\,] + b_h\big)$$
$$h_t = (1 - z_t)\odot h_{t-1} \;+\; z_t \odot \tilde h_t$$
🧹

Reset gate $r_t$

Decides how much of $h_{t-1}$ the candidate is allowed to see. $r\to0$: the candidate is computed from $x_t$ alone, a fresh start.

🎚️

Update gate $z_t$

Blends old and new per unit. $z\to0$: copy the memory unchanged. $z\to1$: overwrite it with the candidate.

✍️

Candidate $\tilde h_t$

A vanilla-RNN step on the reset memory, squashed to $(-1,1)$. It's what the state could become.

Why it doesn't vanish. Look at the first term: $\partial h_t/\partial h_{t-1}$ contains $\mathrm{diag}(1-z_t)$, a path with no weight matrix and no tanh′. When the network learns $z_t\approx0$ for a unit, the gradient and the memory pass straight through, exactly like the LSTM's $f_t\approx1$.

03

One GRU step, by hand

A 1-unit GRU with $x_t = 1$, $h_{t-1} = 0.5$ and small made-up weights. Step through it in the order the cell computes.

Gates → candidate → blend

x=1 · h_(t−1)=0.5
gates r = 0.611σ(0.5x−0.3h+0.1) z = 0.646σ(0.6x+0.4h−0.2)
candidate 0.305r·h = 0.611·0.5 h̃ = 0.816tanh(0.9x+0.8·0.305)
blend 0.177(1−z)·h = 0.354·0.5 0.527z·h̃ = 0.646·0.816 h = 0.704keep + new

$h_t = 0.704$ lies between the old state 0.5 and the candidate 0.816, 64.6% of the way along. A GRU update is always such an interpolation, unit by unit, so the state can never leave $(-1, 1)$, even without an output tanh.

Try b_z = −5: $z\approx0.01$ and $h_t\approx h_{t-1}$ whatever $x_t$ is. The cell is holding its memory. Try b_r = −5: $r\approx0$, so $\tilde h$ depends only on $x_t$ and the candidate forgets the past. Use the two together to see the difference between "don't update" and "update, but from scratch".
05

Memory over time: RNN vs GRU

A single pulse at step 1, then zeros. Both curves are scaled so they start at 1. The GRU's update bias decides how fast it lets go.

How long does a pulse survive?

coral = vanilla RNN h_t · green = GRU h_t · dashed = 10% of the start value

At step 1 the input forces a write. After that $x=0$, so $z_t\approx\sigma(b_z)$, and each step keeps a fraction $1-z_t$ of the state. With $b_z=-3$, $z\approx0.05$ and the state takes about 20 steps to halve. A vanilla RNN has no gate, so its decay is fixed by $w_h$ and the tanh.

Which is better? Large comparisons (Chung et al. 2014; Jozefowicz et al. 2015; Greff et al. 2017) found no consistent winner. GRUs are often as good, and faster. An LSTM with forget bias +1 is a strong baseline, and LSTMs can be better on tasks that need unbounded counting. In practice: try the GRU when compute or data is limited, and try both if accuracy matters.
07

Paper vs PyTorch: the two conventions that trip people up

The same GRU is written in two ways. Mixing them up flips the meaning of $z$ and breaks weight porting.

This page (Chung et al. 2014)PyTorch nn.GRU, cuDNN, ONNX
State updateh = (1−z)⊙h_prev + z⊙h̃h = (1−z)⊙n + z⊙h_prev
Meaning of zfraction of new content takenfraction of old state kept
Where reset appliesbefore the matmul: $W_h(r\odot h)$after it: $r\odot(W_{hn}h + b_{hn})$
ONNX attributelinear_before_reset = 0linear_before_reset = 1
Gate order in weights–r, z, n

The first difference is just a relabelling, $z \leftrightarrow 1-z$. The second is a genuinely different function: reset-after lets the $h$-matmul for all three gates run as one batched multiply, which is faster on GPUs. Cho et al.'s original paper used reset-before. When you export to ONNX or build a TensorRT engine, the exporter sets linear_before_reset=1 for you. If you write a GRU by hand in another runtime, match it.

08

PyTorch: a GRU cell from scratch

Written in PyTorch's own convention, so its outputs match nn.GRUCell once the weights are copied.

import torch, torch.nn as nn

class TinyGRUCell(nn.Module):
    def __init__(self, d, H):
        super().__init__()
        self.x2g = nn.Linear(d, 3 * H)          # W_ir, W_iz, W_in stacked (+ b_i*)
        self.h2g = nn.Linear(H, 3 * H)          # W_hr, W_hz, W_hn stacked (+ b_h*)

    def forward(self, x, h):                  # x (B, d), h (B, H)
        xr, xz, xn = self.x2g(x).chunk(3, -1)
        hr, hz, hn = self.h2g(h).chunk(3, -1)   # one matmul for all gates
        r = torch.sigmoid(xr + hr)
        z = torch.sigmoid(xz + hz)
        n = torch.tanh(xn + r * hn)              # reset AFTER the matmul
        return (1 - z) * n + z * h               # PyTorch: z = keep old

B, T, d, H = 4, 50, 128, 256
cell, x = TinyGRUCell(d, H), torch.randn(B, T, d)
h = torch.zeros(B, H)
for t in range(T):
    h = cell(x[:, t], h)

# check against the built-in cell
ref = nn.GRUCell(d, H)
with torch.no_grad():
    cell.x2g.weight.copy_(ref.weight_ih); cell.x2g.bias.copy_(ref.bias_ih)
    cell.h2g.weight.copy_(ref.weight_hh); cell.h2g.bias.copy_(ref.bias_hh)
h0 = torch.randn(B, H)
print(torch.allclose(cell(x[:, 0], h0), ref(x[:, 0], h0), atol=1e-6))   # True

# full layer: cuDNN-fused, multi-layer
gru = nn.GRU(d, H, num_layers=2, batch_first=True)
out, h_n = gru(x)
print(out.shape, h_n.shape)                    # (4, 50, 256)  (2, 4, 256)
print(sum(p.numel() for p in nn.GRU(d, H).parameters()))   # 296,448
One state, so no tuple. nn.GRU returns (out, h_n), while nn.LSTM returns (out, (h_n, c_n)). Swapping one for the other in existing code is the most common source of unpacking errors.
09

Where GRUs are used, and how to deploy them

🌐

Machine translation

The GRU was introduced in Cho et al.'s RNN encoder-decoder (2014). Bahdanau et al.'s attention model (2015) also used gated units of this kind.

🎙️

Speech

DeepSpeech 2 compared vanilla-RNN and GRU recurrent layers after a convolutional front end. Small streaming ASR and keyword-spotting models often use GRUs.

📈

Time series & edge

Forecasting, sensor data and on-device models, where ¾ of the LSTM's compute and a single state vector matter.

Deployment stepWhat to watch
ONNX exportnn.GRU exports to the ONNX GRU operator with linear_before_reset=1. Give h0 as an explicit input and h_n as an output.
Streaming inferenceRun one chunk, keep h_n, feed it back as h0 for the next chunk. This is the GRU version of carrying (h, c) in an LSTM predictor.
BidirectionalDoubles the output to 2H and needs the whole sequence, so it is offline only.
Parity checkCompare PyTorch and ONNX Runtime outputs with a tolerance such as atol=1e-4. Run the same check for TensorRT with Polygraphy, as in the deployment guide.

Interview questions

QuestionStrong short answer
What are the GRU's gates?Reset $r$ (how much past the candidate sees) and update $z$ (how much to blend the candidate into the state). Both are sigmoid. The candidate uses tanh.
How does a GRU avoid vanishing gradients?$h_t = (1-z)\odot h_{t-1} + z\odot\tilde h$ gives a direct path $\mathrm{diag}(1-z)$ with no weight matrix. With $z\approx0$, memory and gradient pass through unchanged.
GRU vs LSTM in one line?The GRU merges forget and input into one update gate, merges cell and hidden state, and drops the output gate. It has 3 weight blocks instead of 4.
Parameter count?$3H(d+H+1)$, or $3H(d+H)+6H$ in PyTorch. With d=128, H=256: 296,448.
What does $r=0$ mean?The candidate is computed from $x_t$ only, so it forgets the history when proposing new content. That differs from $z=0$, which keeps the old state and ignores the candidate.
Why is $h_t$ bounded without an output tanh?It is a convex combination of $h_{t-1}$ and $\tilde h_t$, both in $(-1,1)$, so it stays in $(-1,1)$.
What is linear_before_reset?Whether the reset gate multiplies $h$ before or after the recurrent matmul. PyTorch and cuDNN apply it after (value 1), which lets all three recurrent matmuls be batched.
Reset what the candidate sees. Update by blending.
