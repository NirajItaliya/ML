Networks that remember.

A feed-forward network sees one input and forgets it. A recurrent neural network reads a sequence one step at a time and carries a small memory, the hidden state, from each step to the next. This page builds that idea from one equation, with a step-through demo and live sliders.

01

Why a network needs memory

"I grew up in France, so I speak fluent ___." The answer depends on a word that appeared six words earlier. To predict it, a model has to carry information forward.

A feed-forward network maps one fixed-size input to one output. Sequences break that in two ways. First, their length varies: a sentence can be 3 words or 300, and a clip of audio can be 1 second or 1 hour. Second, order carries meaning: "dog bites man" and "man bites dog" use the same words.

A recurrent neural network (RNN) solves both with one trick. It processes the sequence one element at a time and keeps a vector $h_t$, the hidden state, that summarises everything it has seen so far. At each step it combines the new input with the old summary to make a new summary.

📖

Reading a book

You don't re-read every page for each new sentence. You keep a running mental summary and update it as you go. That summary is $h_t$.

🔁

One cell, reused

The same weights process step 1, step 2 and step 500. That is why an RNN can handle any length without adding parameters.

🎙️

Speech frames

Audio arrives as 100 frames per second. An RNN can consume them as they arrive, which makes it naturally streaming.

02

The recurrent cell: one equation

Everything about a vanilla RNN (also called an Elman network) is in this line:

$$h_t = \tanh\!\big(W_{xh}\,x_t + W_{hh}\,h_{t-1} + b_h\big)$$

Read it left to right. $W_{xh}x_t$ asks "what is new?", and $W_{hh}h_{t-1}$ asks "what do I remember?". The two are added, and $\tanh$ squashes the result into $(-1, 1)$ so it can't grow without limit. The result $h_t$ is both the cell's output at step $t$ and its memory for step $t+1$. If you need a prediction at each step, add a linear head:

$$y_t = W_{hy}\,h_t + b_y \qquad \hat p_t = \mathrm{softmax}(y_t)$$

The first state $h_0$ is usually a vector of zeros.

SHAPES · BATCH B · INPUT SIZE d · HIDDEN SIZE H · OUTPUT SIZE V
TensorShapeMeaning
x_t(B, d)input at step t, e.g. a word embedding or an 80-bin log-Mel frame
h_t(B, H)hidden state, the running summary
W_xh(H, d)input → hidden
W_hh(H, H)hidden → hidden: the recurrence
W_hy(V, H)hidden → output (optional head)
Parameter count. One RNN layer has $H\cdot d + H\cdot H + H = H(d+H+1)$ parameters. With $d=128$ and $H=256$ that is 98,560, no matter whether the sequence has 10 or 10,000 steps. PyTorch keeps two bias vectors ($b_{ih}$ and $b_{hh}$), so nn.RNN(128, 256) reports 98,816.
03

Unrolling: watch the memory move

"Unrolling" means drawing the same cell once per time step. It is the same network, just laid out in time. Step through a tiny example with scalar weights $W_{xh}=0.5$, $W_{hh}=0.8$, $b=0$ and the input $x=[1,0,0,0]$.

A single pulse travelling through time

h_t = tanh(0.5·x_t + 0.8·h_(t−1))
input x_t 1t=10t=20t=30t=4
pre-activation 0.5000.5·1+0.8·00.3700.8·0.4620.2830.8·0.3540.2210.8·0.276
hidden h_t 0.462tanh0.354tanh0.276tanh0.217tanh

Two lessons hide in those four numbers. The input "1" at step 1 is still visible at step 4, so the network does remember. But it shrinks by roughly 0.8 per step, so after 20 steps almost nothing is left. That fading is the central weakness of vanilla RNNs, and section 06 explains why it also happens to the gradients.

Try $w_h = 0.3$: the memory is gone in about 3 steps. Try $w_h = 1.5$ with "constant 1": $h_t$ slams into tanh's ceiling of 1 and stays there (saturation), and the gradient through a saturated tanh is almost 0. A plain RNN has no good setting that gives long, stable memory. LSTM fixes this.

06

Backprop through time and the vanishing gradient

To train an RNN you unroll it and run ordinary backpropagation over the unrolled graph. This is called backpropagation through time (BPTT). The loss at step $T$ has to send a gradient all the way back to step 1.

By the chain rule, the gradient from $h_T$ to $h_1$ is a product of one Jacobian per step:

$$\frac{\partial h_T}{\partial h_1} = \prod_{t=2}^{T} \frac{\partial h_t}{\partial h_{t-1}} = \prod_{t=2}^{T} \mathrm{diag}\big(1-h_t^2\big)\,W_{hh}$$

Each factor contains the same matrix $W_{hh}$, multiplied by a tanh derivative that is at most 1. Multiply a number by itself many times and it either shrinks to zero (if its size is below 1) or blows up (if it is above 1). For matrices, the size that matters is the largest singular value of $W_{hh}$.

07

PyTorch: from scratch, then nn.RNN

Writing the loop yourself once makes the built-in layer obvious.

import torch, torch.nn as nn

class TinyRNN(nn.Module):
    def __init__(self, d, H):
        super().__init__()
        self.W_xh = nn.Linear(d, H)               # includes b_h
        self.W_hh = nn.Linear(H, H, bias=False)
        self.H = H

    def forward(self, x):                      # x: (B, T, d)
        B, T, _ = x.shape
        h = x.new_zeros(B, self.H)                # h_0 = 0
        outs = []
        for t in range(T):                    # sequential: can't parallelise over T
            h = torch.tanh(self.W_xh(x[:, t]) + self.W_hh(h))
            outs.append(h)
        return torch.stack(outs, dim=1), h    # (B, T, H), (B, H)

x = torch.randn(4, 50, 128)                   # batch 4, 50 steps, 128 features
out, h_T = TinyRNN(128, 256)(x)
print(out.shape, h_T.shape)                    # (4, 50, 256)  (4, 256)

# the built-in, cuDNN-fused version
rnn = nn.RNN(128, 256, num_layers=2, batch_first=True)
out, h_n = rnn(x)
print(out.shape, h_n.shape)                    # (4, 50, 256)  (2, 4, 256)
Shape trap. h_n is (num_layers × num_directions, B, H), with the layer axis first, even with batch_first=True. Only the input and out are batch-first.

For a classifier (many → one), use h_n[-1], the top layer's last state, and put a nn.Linear(H, num_classes) on it. For padded batches of different lengths, wrap the input with nn.utils.rnn.pack_padded_sequence so padding steps don't overwrite the state.

Where RNNs stand today

Transformers replaced RNNs for most large models after 2017, but recurrence never disappeared. It is still the right tool when you need constant memory per step and true streaming.

RNN / LSTMTransformer
Training over T stepsT sequential steps: slow on GPUsall positions in parallel
Inference memory per new tokenconstant: one $h_t$grows with T (KV cache)
Cost of the whole sequence$O(T)$$O(T^2)$ attention
Long-range dependencieshard: everything must pass through $h_t$direct: any token can attend to any other
Streamingnaturalneeds chunking and cache tricks

09

Interview questions

QuestionStrong short answer
What is the hidden state?A fixed-size vector $h_t$ that summarises inputs $x_1..x_t$. It is both the step's output and the memory passed to step $t+1$.
Why share weights across time?It handles any sequence length with a fixed parameter count, and a pattern learned at one position works at every position.
Why tanh rather than ReLU?tanh is bounded, so repeated application can't blow up the state. ReLU RNNs can work but need careful init (e.g. IRNN, identity $W_{hh}$).
What causes vanishing gradients in RNNs?BPTT multiplies one Jacobian $\mathrm{diag}(1-h^2)W_{hh}$ per step. If its largest singular value is below 1, the product decays exponentially with distance.
Exploding vs vanishing fix?Exploding: clip the gradient norm. Vanishing: change the architecture (LSTM/GRU), use orthogonal init, or use skip connections.
What is truncated BPTT?Backprop only through the last k steps of a long stream, carrying the state forward with h.detach(). Bounded memory, but dependencies longer than k can't be learned.
Bidirectional RNN?One RNN reads forward and one backward, and their states are concatenated (2H). It sees future context, so it can't stream. Diagram: BiRNN sheet.
